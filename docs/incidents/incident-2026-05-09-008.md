# 商品保存時に "Cannot read properties of null (reading 'trim')" でクラッシュ

## 1. 発生日時・症状（ユーザー視点）

- **発生**: 2026-05-09（incident-007 の AI ラベル抽出マルチカテゴリ対応後）
- **検知**: dev ログ monitor で `TypeError: Cannot read properties of null (reading 'trim')` を検知
- **症状**:
  - **正しい動作**: 日本酒・焼酎など、`country` や一部フィールドが render されないカテゴリでも保存できる
  - **実際の動作**: `createProduct` が unhandledRejection で 500、ユーザはエラー画面

## 2. 影響範囲

- **対象ロール**: admin
- **対象テナント**: 全テナント
- **影響件数**: 日本酒 / 焼酎 / ジン / ウイスキー / その他カテゴリの新規・編集すべて
- **業務影響**: ワイン以外の商品が一切登録できない

## 3. 原因

- `extractProductValues` が `(formData.get("country") as string).trim()` のように、`formData.get` が null を返した場合を考慮せず `.trim()` を呼んでいた
- ワイン以外のカテゴリでは ProductForm が `country` / `region` / `category` などを条件 render しないため、formData にそれらのキーが含まれない → null
- TypeScript の `as string` キャストが null を見逃した

## 4. 対応

- `app/(admin)/admin/products/actions.ts` の `extractProductValues` に null セーフヘルパ追加:

  ```ts
  const str = (key: string): string => {
    const v = formData.get(key);
    return typeof v === "string" ? v.trim() : "";
  };
  ```

- `name / producer / region / country / category / type / comment / grape_variety / image_url` 全部 `str(key)` 経由に置換

## 5. 学び

- **`formData.get(key)` は常に `FormDataEntryValue | null`**。`as string` キャストは嘘が混入する
- 条件 render するフォーム要素を増やしたら、Server Action 側の null セーフを必ず確認
- TypeScript `as` キャストは「型を主張する」だけでランタイム保証ゼロ。null チェックは別途必須
