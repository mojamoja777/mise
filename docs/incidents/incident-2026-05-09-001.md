# AI ラベル抽出後の地域がほぼ「その他」に潰れ、コメントに想定小売価格帯が混入

## 1. 発生日時・症状（ユーザー視点）

- **発生**: 2026-05-09（P0 ランタイム動作確認 C-2 工程で発見）
- **検知**: 佐川によるドイツ Landwein Main のラベル写真を使った検証
- **症状**:
  - **正しい動作**: AI が読み取った産地（フランケン / Landwein Main 等）が地域フィールドに入る
  - **実際の動作**: 地域ドロップダウンの選択肢が「その他」しか無く、AI 抽出結果が「その他」に潰れる。さらにコメント欄の末尾に「想定小売価格帯: ¥4000-7000」が混入していた

## 2. 影響範囲

- **対象ロール**: admin（商品登録）
- **対象テナント**: 全テナント
- **影響件数**: 既存登録済みデータには影響なし。新規登録のドイツ / スペイン / オーストリア / ポルトガル / オーストラリア / NZ / 南アフリカ / アメリカ / チリ / 日本 / その他多数の国で同症状
- **業務影響**: 体験劣化（admin が手動で地域を補正する手間 / 価格帯記載が顧客に見られる懸念）

## 3. 原因（技術的根本原因）

- **直接原因 ①（地域）**: `lib/product-constants.ts` の `WINE_REGIONS` マスタが、フランス・イタリア以外は `["その他"]` のみ。さらに `ProductForm.tsx` 338 行目が `<select>` だったため自由入力もできなかった
- **直接原因 ②（価格帯）**: `lib/ai/extract-prompt.ts` 38 行目で `estimated_price_range_jpy` を AI に出力させ、`components/admin/NewProductPanel.tsx` の `buildComment` がそれを comment 欄に追記していた。一方 `comment-generate.ts` のシステムプロンプトでは「価格や在庫、希少性には言及しない」と明示しており、抽出側と生成側で方針が不整合
- **メカニズム**:
  - `NewProductPanel.tsx` の `normalizeRegion` は候補に無いと「その他」へフォールバックする実装だった
  - 候補が「その他」しか無い 14 ヶ国はすべて潰れる
- **見落とし**:
  - WINE_REGIONS の充足状況がテストされていなかった
  - extract-prompt.ts と comment-generate.ts のフィールド方針が分離されており、整合性のチェックが無かった

## 4. 対応

- **コミット**: 未（本セッションでまとめてコミット予定）
- **変更内容**:
  - `lib/product-constants.ts` — WINE_REGIONS で 14 ヶ国に主要産地を 5〜15 件ずつ追加
  - `components/admin/ProductForm.tsx` 334-352 — region フィールドを `<select>` から `<input list="wine-region-list">` + `<datalist>` に変更（候補も出る + 自由入力 OK）
  - `components/admin/NewProductPanel.tsx` 162-164 — `normalizeRegion` のフォールバックを「その他」から AI 抽出の生文字列に変更
  - `components/admin/NewProductPanel.tsx` 36-39 — `buildComment` から「想定小売価格帯」行を削除
  - `lib/ai/extract-prompt.ts` 38 — プロンプトから `estimated_price_range_jpy` キー削除（トークン節約）
  - `types/wine-extraction.ts` 28 — `WineExtractionResult` から同フィールド削除
- **検証手順**:
  - `npx tsc --noEmit` ✅
  - 同じドイツワイン写真で C-2 を再試行（ユーザ実施待ち）
- **ロールバックプラン**: 6 ファイルの diff を一気に revert すれば従来挙動に戻る。スキーマ変更なし

## 5. 学び（次回どう動くか）

- **再発防止**:
  - 入力候補ドロップダウン × AI 抽出の組み合わせは「候補に無い → その他に潰れる」が起きやすい。datalist + free-text input の組み合わせが安全
  - extract と generate のプロンプトは方針を一致させる（特に「言及しない項目」のホワイトリスト / ブラックリスト）
- **チェックリスト追加**:
  - 新しい AI 抽出フィールドを増やす時、それが UI のどこに流れるかを必ずトレース
  - 候補マスタの充足度を検証してから `<select>` を使う（足りなければ datalist）
- **設計上の教訓**:
  - フォーム入力の候補マスタは「閉じた集合」と「開いた集合」を区別する。閉じた集合（税区分・カテゴリ）は select、開いた集合（地域・品種・生産者）は datalist + 自由入力
