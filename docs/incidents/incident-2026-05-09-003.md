# 「AIで生成」ボタンが既存コメントを警告なく上書き / AI コメントを新規作成時のデフォルトに統合

## 1. 発生日時・症状（ユーザー視点）

- **発生**: 2026-05-09（incident-001 修正後の C-2 再検証時）
- **検知**: 佐川がドイツワインで C-1 → 自動入力されたコメント（appellation / アルコール度数 / 認証 など多数行）を確認後、コメント欄右上の「⚡ AIで生成」ボタンを押下
- **症状**:
  - **正しい動作**: 既存コメントを保護する（追記 or 確認ダイアログ）か、そもそも 2 系統のコメント生成が混在しないこと
  - **実際の動作**: 既存の詳細メタデータ付きコメントが警告なく短いテイスティングノートに丸ごと差し替わった

## 2. 影響範囲

- **対象ロール**: admin（商品登録 / 編集）
- **対象テナント**: 全テナント
- **影響件数**: 商品登録フローを使う admin 全員
- **業務影響**:
  - 既存コメントを失うリスク（admin が手で書き足したテキストも含めて消える）
  - 「AI 抽出フローのコメント」と「AI 生成ボタンのコメント」の 2 系統が UX 上混乱を招く

## 3. 原因（技術的根本原因）

- **直接原因 ①**: `components/admin/ProductForm.tsx:88` で `setComment(json.comment)` が無条件にテキストを上書き。確認ダイアログ無し
- **直接原因 ②（設計）**: AI コメント生成パスが「ラベル抽出時の `buildComment` メタダンプ」と「ボタン経由の `generate-comment`」の 2 系統に分かれており、それぞれ別の文体・構成・粒度で出力。ユーザは「ボタンの方が綺麗だから差し替えたい」「でも既存メタも残したい」の板挟みになる
- **見落とし**:
  - 破壊的アクション（テキスト全置換）にも関わらず確認 UI 無し
  - 2 系統の AI 出力が併存することの UX レビュー漏れ

## 4. 対応

ユーザ指示「AIで生成ボタンを無くしデフォルトでAIによるコメントを最初の作成時に入れる」に従い、**ボタンを廃止し、ラベル抽出時に自動で polished comment を生成して seed に流す** 設計に統合。

- **コミット**: 未（本セッションでまとめてコミット予定）
- **変更内容**:
  - `components/admin/ProductForm.tsx` 47-94, 437-459 — `aiPending` / `aiError` / `comment` state と `generateCommentWithAI` ハンドラを削除。textarea を controlled → uncontrolled (`defaultValue={product?.comment ?? ""}`) に変更。コメント欄右上の「⚡ AIで生成」ボタン削除
  - `components/admin/AILabelExtractor.tsx` 13-20, 98-105, 184 — `onExtracted` を `void | Promise<void>` 型に変更し、`await onExtracted(json.data)` で親の chain 完了まで loading 維持。ボタン文言を「解析 + コメント生成中… (15〜30秒)」に更新
  - `components/admin/NewProductPanel.tsx` — `buildComment` を `fallbackComment`（tasting_note のみ返す）に簡素化。`fetchPolishedComment` 関数を新設し generate-comment API を呼ぶ。`AILabelExtractor.onExtracted` を async 化し、抽出後に polished comment を取得してから一発で `setSeed`
- **検証手順**:
  - `npx tsc --noEmit` ✅
  - 新規登録ページで画像アップロード → 解析 + コメント生成中… 表示 → 約 15-30 秒で全フィールド + polished comment が一発で入る
  - 編集ページでコメント欄に「AI で生成」ボタンが存在しないこと
- **ロールバックプラン**: 3 ファイルの diff を revert すれば従来挙動（ボタン + メタダンプ）に戻る

## 5. 学び（次回どう動くか）

- **再発防止**:
  - **テキストエリアを「全置換するアクション」は原則禁止**。追記・別フィールドへ・確認ダイアログのいずれかを必須にする
  - 同じ目的（コメント生成）に複数経路を作らない。出口は 1 つに統一
- **チェックリスト追加**:
  - フォームに「⚡ AI 生成」系ボタンを足す前に、既存値をどう扱うか（保護 / 追記 / 上書き確認）を必ず仕様書化
  - AI 出力を 2 系統で出すなら、それぞれ別フィールド or 別フェーズに分離
- **設計上の教訓**:
  - **「自動デフォルト」と「手動再生成」は別物**。デフォルトは作成時 1 回、再生成は明示的な意思表示（modal で「現在の内容を破棄して再生成」確認）で。今回はデフォルト 1 系統に絞った
  - polished comment は extract と同じ chain に統合すると、UX のシームレスさと出力の一貫性が両立する
