# チャットの既読更新 Server Action が render 中に revalidatePath を呼びエラー

## 1. 発生日時・症状（ユーザー視点）

- **発生**: 2026-05-09（pre-existing。incident-005 のカート通知実装中に dev ログで顕在化）
- **検知**: dev サーバの monitor で `Route /buyer/chat used "revalidatePath /buyer/chat" during render which is unsupported` を多数検知
- **症状**:
  - **正しい動作**: チャットページを開くと既読時刻が更新され、ヘッダー / 下部ナビの未読バッジが正しく更新される
  - **実際の動作**: チャットページを開く度に Next.js が render-context から revalidatePath を呼ばれてエラーログ出力（実害は無いが大量に出る）

## 2. 影響範囲

- **対象ロール**: buyer（顕在）/ admin（潜在、現状呼び出し無し）
- **対象テナント**: 全テナント
- **影響件数**: チャットページ訪問回数 × エラー件数
- **業務影響**:
  - 機能としては動いている（既読時刻は更新される）
  - 大量のエラーログが本物のエラーを埋もれさせる
  - Next.js 16 の今後の更新で render 中 revalidate が「警告」から「ハードエラー」に格上げされる可能性

## 3. 原因（技術的根本原因）

- `app/(buyer)/buyer/chat/page.tsx:20` で `await markBuyerThreadRead()` を **page render 中に呼んでいる**
- `markBuyerThreadRead`（`app/(buyer)/buyer/chat/actions.ts:83`）が `revalidatePath("/buyer/chat")` を実行
- Next.js 16 では「render 中の revalidate」を unsupported としてエラー
- 同じ Server Action パターンは `app/(admin)/admin/chat/actions.ts:104` の `markAdminThreadRead` にも存在（こちらは現状未呼出だが潜在）

## 4. 対応

### 4-A. 最小修正

両 actions から `revalidatePath` を削除し、コメントで理由を残した。

- `app/(buyer)/buyer/chat/actions.ts` `markBuyerThreadRead` — `revalidatePath("/buyer/chat")` 削除
- `app/(admin)/admin/chat/actions.ts` `markAdminThreadRead` — `revalidatePath("/admin/chat")` 削除

### 4-B. 副作用と許容判断

未読バッジは next navigation 時に層（layout）が再フェッチされるタイミングで更新される。同セグメント内の遷移では layout キャッシュにより即時反映されない可能性があるが、致命的ではない（次に別ページへ遷移すれば更新される）。

### 4-C. 検証手順

- `npx tsc --noEmit` ✅
- /buyer/chat を開いて dev ログに `revalidatePath ... during render` が出ないこと
- 既読時刻が DB で更新されていること（機能影響なし）

### 4-D. ロールバックプラン

`revalidatePath` 行を戻すだけ。エラーログは出るが機能は動く。

## 5. 学び（次回どう動くか）

- **再発防止**:
  - **page render 中に Server Action を `await` で呼んだ場合、その Action 内では revalidatePath / revalidateTag を絶対に呼ばない**
  - 既読系の更新は理想的には `useEffect` から fire-and-forget するクライアント側パターンの方が綺麗
- **チェックリスト追加（Server Action 設計時）**:
  - [ ] この action は page render 中から呼ばれる可能性があるか
  - [ ] あるなら revalidatePath / revalidateTag は使わない（または別の経路に分ける）
  - [ ] mutation 系（既読 / counter インクリメント）は client useEffect でやるのが Next.js 16 流
- **設計上の教訓**:
  - Next.js 16 は **副作用の文脈分離**が厳格。render = pure / mutation = action / cache invalidation = post-action only
  - HANDOFF.md の Next.js 16 注意点セクションに **「render 中 revalidate 禁止」** を追記して将来再発を防止
